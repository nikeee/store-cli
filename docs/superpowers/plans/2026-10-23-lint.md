# store lint Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `store apple lint <dir>` and `store google lint <dir>`: offline checks of a metadata directory that report every problem at once, as errors and warnings, locally and as GitHub annotations.

**Architecture:** A small `internal/lint` package holds findings, the result, its text form and the exit error. Each store gets `Lint(o PushOptions, notesDir string) (*lint.Result, error)` next to its `ReadPushDir`, built on the same reader and validator, which now collect problems instead of stopping. Rules where the store API rejects a value move into the shared field and image tables, so `push` fails early on them too.

**Tech Stack:** Go, cobra, existing `clierr`, `metadata`, `media`, `output` packages.

**Spec:** `docs/superpowers/specs/2026-10-23-lint-design.md` (rule numbers below refer to it).

## Global Constraints

- No en or em dashes anywhere, comments short and English, messages lower case without trailing period.
- Offline: lint never builds an API client and needs no credentials.
- One rule lives in one place; every check `push` does is a lint error from the same code.
- Sources of new limits cited in code comments with retrieval date 2026-10-23.
- `go generate ./...` after CLI or table changes; `go test ./...` and `go vet ./...` green before each commit.

## Review Focus

- A directory with both a broken image and an unknown device folder: both are reported, not only the first.
- A healthy directory (valid texts, iPhone 6.9 and iPad 13 sets, phone 9:16 1080x1920 x4, feature graphic, icon) yields zero findings on both stores.
- Keywords with multi-byte runes: the byte limit and the column of the overflow are right.
- On GitHub Actions every finding is annotated exactly once (errors through the final error, warnings by the command).
- `--only texts` skips all image rules, including the presence warnings.

### Task 2: `internal/lint` package and warning annotations

**Files:**
- Create: `internal/lint/lint.go`, `internal/lint/lint_test.go`
- Modify: `internal/output/github.go` (`func (p *Printer) AnnotateWarning(is clierr.Issue)`, no-op off GitHub)

**Interfaces:**
- Produces:
  - `type Severity string` with `Error = "error"`, `Warning = "warning"`
  - `type Finding struct { Severity; File string; Line, Col int; Message string }` (json `severity,file,line,col,message`, file/line/col omitempty); `func (f Finding) Issue() clierr.Issue`
  - `type Result struct { Findings []Finding; Errors, Warnings int }` (json `findings,errors,warnings`)
  - `func (r *Result) Add(s Severity, is clierr.Issue)`; `func (r *Result) AddError(err error)` (each issue of a `*clierr.Error`, else one file-less finding; nil ignored)
  - `func (r *Result) Sort()`: file-less first (insertion order), then file, line, col
  - `func (r Result) Err(strict bool) error`: nil unless errors, or strict and warnings; message `2 errors, 1 warning`; `Issues` = the error findings
  - `func (r Result) RenderText(w io.Writer, s output.Styles) error`: `file:line:col: error: msg` (parts as known), file-less `error: msg`, then summary line or `no problems`

- [ ] Tests: AddError keeps issues and file-less text; Sort order; Err for (errors), (warnings, strict false/true); RenderText exact lines; AnnotateWarning writes `::warning file=..,line=..::msg` only with AnnotateGitHub.
- [ ] Implement, test, commit `feat(lint): findings, result and warning annotations`.
