# store CLI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Each task is a GitHub issue; its body holds the steps with checkbox (`- [ ]`) syntax for tracking.

**Goal:** A public Go CLI `store` that drives App Store Connect and Google Play through their official APIs, for CI and local use, as one static binary.

**Architecture:** cobra commands in `internal/cli` stay thin: parse flags, call one method on a domain service (`internal/apple.Service`, `internal/google.Service`), hand the typed result to `internal/output`. Domain services talk to a client generated from Apple's OpenAPI spec and to Google's official generated client. Everything a user sees as "the listing" is described once in tables in `internal/metadata` and `internal/media`, which drive flags, validation, `init`, `push` and `pull`.

**Tech Stack:** Go 1.27, cobra/pflag, generated App Store Connect client (generator chosen in the spike), `google.golang.org/api/androidpublisher/v3`, `howett.net/plist`, `github.com/moonrhythm/toon`, lipgloss (colors, tables), goreleaser, golangci-lint.

**Spec:** `docs/superpowers/specs/2026-10-21-store-cli-design.md`. Command reference (flags, results, layouts): `docs/commands.md`.

**Tasks:** the GitHub issues of `nikeee/store-cli`, root issue #1. This file holds what every task shares; task details live only in the issues.

## Global Constraints

- Module `github.com/nikeee/store-cli`; main package `cmd/store`; binary `store`.
- Go 1.27 (`go 1.27` in `go.mod`); generator and doc tools pinned with the `tool` directive in `go.mod`, run via `go tool`.
- Targets: linux/darwin x amd64/arm64, `CGO_ENABLED=0`.
- Credentials only from env: `APPLE_APPSTORE_ISSUER_ID`, `APPLE_APPSTORE_API_KEY_ID`, `APPLE_APPSTORE_API_PRIVATE_KEY`, `GOOGLE_PLAY_SERVICE_ACCOUNT_JSON`. App defaults: `APPLE_APPSTORE_BUNDLE_ID`, `GOOGLE_PLAY_PACKAGE_NAME`. Output default: `STORE_OUTPUT`.
- Official APIs only. Apple spec: `api/apple/openapi.oas.json` (4.5.1). No web-session endpoints.
- All user-facing text in English. No en or em dashes anywhere (docs, help, output, comments); use `-`.
- stdout = result only; progress, warnings, errors = stderr. Exit codes 0 / 1 / 2 as in `docs/commands.md`.
- No interactive prompts. No secret, token or auth header in any output, including `--verbose`.
- Every fact lives in one place (design doc, "Single source of truth"). If you are about to write a second list of fields, devices, image types, locales, env var names or flags, import the existing one instead.
- Generated code is committed and reproducible with `go generate ./...`; CI fails on drift.
- No live API calls in tests. Fixtures are built from the response fields `../pd/scripts/release/*.ts` reads (copied into the issues where needed) plus the spec's schemas.

## Working agreement for agents

- One issue = one branch `issue-<n>-<slug>` = one PR with `Closes #<n>`. Do not start an issue whose blockers are open.
- TDD: write the tests named in the issue first, see them fail, implement, see them pass.
- Before pushing: `go generate ./... && git diff --exit-code`, `go vet ./...`, `golangci-lint run`, `go test ./...`.
- Conventional commits (`feat:`, `fix:`, `test:`, `docs:`, `chore:`, `ci:`), small commits.
- Match the surrounding code: naming, comment density, error style (`clierr`), test style (table tests, `testutil` fakes, golden files).
- If the issue and `docs/commands.md` disagree, `docs/commands.md` wins; note it in the PR.
- Command help texts (`Short`, `Long`, `Example`) are copied from `docs/commands.md`.
- Every mutating command registers `--dry-run` (`cli.addDryRun`): it performs the reads, returns the result it would produce (with `Change.Action` values where a plan exists), and sends no POST, PATCH, PUT or DELETE. Each task adds one `...DryRun...` test asserting the fake server saw only GET requests (Google: edit inserted and deleted, never committed).

## Review Focus

Inputs and conditions the spec implies that most likely bite a user, and the test that pins each:

1. **Credentials in CI secrets come in every shape**: PEM with real newlines, with literal `\n`, with surrounding quotes or whitespace, a path instead of content; service account JSON as content or path. Expected: all accepted, or one clear error naming the variable and never echoing the value. Test `TestLoadAppleCredentialsShapes` and `TestLoadGoogleServiceAccountShapes` in A1.
2. **Apple processing is slow and stalls**: builds take minutes to appear, screenshots sit in `UPLOAD_COMPLETE` for minutes. Expected: polling with configurable `--timeout`, progress on stderr, timeout error that says what and how long it waited. Tests `TestUploadBuildWaitsForBuild` (C4) and `TestUploadScreenshotSlowProcessing` (D3).
3. **Failure in the middle of `push`**: the third locale fails. Expected: exit 1, stderr shows which changes were applied and which not; on Google the edit is deleted so nothing is half-published. Tests `TestApplePushPartialFailure` (D6) and `TestGooglePushDeletesEditOnFailure` (F7).
4. **Locales that differ between stores**: `it`, `es-MX`, `zh-Hans` given to Google; release notes for languages the Play listing does not have. Expected: mapped automatically; unsupported languages dropped with a warning instead of a 400. Tests `TestToPlay` (F1) and `TestPromoteDropsNotesForUnlistedLanguages` (F3).
5. **Non-ASCII text against limits**: German umlauts, CJK, emoji in names and keywords. Expected: limits count characters (runes), not bytes; the error names file, field, limit and actual length. Test `TestValidateTextsCountsRunes` in M1.
